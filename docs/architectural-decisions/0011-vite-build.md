# ADR-0011. Переезд на Vite: Phaser из npm, код по модулям

- **Дата:** 2026-08-21
- **Статус:** принято
- **Решает:** этап 9 маршрута — сборку, отложенную дважды
- **Пересматривает:** ADR-0001 в части «один файл», «Phaser с CDN», «сборки нет»
- **Закрывает триггер:** ADR-0006 («переезд после закрытия этапа 7»)
- **Двигает границу:** ADR-0004 — см. раздел «Что ломается в QA-оснастке»

## Контекст

ADR-0001 зафиксировал: Phaser с CDN, один `index.html`, сборки нет — и записал триггер
пересмотра на 1500 строк. Триггер сработал ещё на этапе 5. ADR-0006 разрешил не переезжать до
конца MVP и назначил новый триггер — закрытие этапа 7.

Оба срока прошли. Этап 7 отменён (ADR-0008), ветка 8.x закрыта целиком, `index.html` —
**2505 строк**. Дальше откладывать нечем: незакрытый триггер это не решение, а долг.

Сроки — не единственная причина. От сборки зависят следующие этапы:

- **этап 10, спрайты.** Класть картинки рядом с монолитом на 2500 строк и грузить их
  относительными путями можно, но каждый новый ассет — это ещё одна строка в `preload()` и
  ещё одна точка отказа в архиве для модерации;
- **этап 14, архив для модерации.** Площадка требует **самодостаточный** архив. Сейчас игра
  тянет Phaser с `cdn.jsdelivr.net` — то есть без интернета не работает вовсе. Это не
  придирка на будущее, это прямой критерий приёмки в `GAME_SPEC.md`, раздел 18, этап 9:
  «игра работает из папки **без интернета**».

## Решение

Переезжаем на **Vite 8**, Phaser ставится из npm версией `4.2.1` (точный номер, как требовал
ADR-0001), код `index.html` раскладывается по модулям в `src/`.

Разбивка **механическая**: `CONFIG`, хелперы, семь сцен, точка входа. Код переносится один
в один — ни одной правки логики, ни одного изменённого числа в `CONFIG`.

`GameScene` (~1350 строк) в этом ADR **не разбирается**. Причина процедурная: смешать в одной
сессии смену системы сборки и рефакторинг главной сцены значит потерять возможность понять,
что именно сломалось, если сломается. Разбор — отдельной задачей, по той же логике, по которой
ADR-0006 отказался переезжать в одной сессии с правкой ввода.

## Что ломается в QA-оснастке

`tools/qa/harness.js` доставал игру перехватом присваивания `window.Phaser`: подменял
`Phaser.Game` своим конструктором и ловил экземпляр. Под ESM-импортом `window.Phaser` не
присваивается вовсе — перехватывать нечего.

В `src/main.js` появляется одна строка: `window.game = game`.

**Это двигает границу ADR-0004,** где записано: «в `index.html` нет и не должно появиться ни
одной строки ради тестов». Записываем честно, вместо того чтобы сделать молча:

- перехват существовал **только потому**, что ручки к игре не было — экземпляр лежал в
  модульной области. Это была компенсация отсутствия ручки, а не принцип;
- ручка полезна и без тестов: из консоли браузера `game.scene.getScene('GameScene')` — первое,
  что нужно при отладке;
- остальная часть границы ADR-0004 **в силе**: `window.__qa` со всеми методами замера
  по-прежнему живёт в оснастке и вставляется в страницу снаружи
  (`page.evaluateOnNewDocument`), а не в коде игры.

Второе изменение оснастки — она поднимает статический сервер над `dist/`, а не над корнем
репозитория, и собирает `dist/` сама, один раз на процесс node. Без этого замер мог бы
молча снять числа со вчерашней сборки, а числа тут — доказательная база.

## Цена решения

| Было | Стало |
|---|---|
| Правый клик по `index.html` → Open with Live Server | `npm run dev` |
| GitHub Pages отдаёт репозиторий как есть | Pages собирается через GitHub Actions из `dist/` |
| `npm install` нужен только для QA | нужен и для запуска игры |
| Зависимостей у игры нет | зависимость одна: `phaser` |

Отдельно стоит записать **выгоду, которой не ждали**: dev-сервер Vite раздаёт игру по `http`.
Ловушка «открыл двойным кликом → сэмплы не грузятся по CORS → звука нет» исчезает насовсем.
Именно она съела все плейтесты звука с этапа 4.

## Что остаётся запрещённым

ADR-0011 разрешает **ровно две** зависимости: `vite` (сборка) и `phaser` (игра).
Правило `CLAUDE.md` в силе: TypeScript, UI-фреймворк, сервер, аналитика, любой плагин Vite —
каждое требует нового ADR, а не тихого `npm i`.

## Альтернативы

- **Остаться на CDN, просто разложить код по `<script>`-тегам.** Отклонено: не решает
  требование самодостаточного архива, а порядок тегов — это ручное управление зависимостями.
- **Взять esbuild/rollup напрямую.** Отклонено: dev-сервер с горячей перезагрузкой пришлось
  бы собирать самому, а он тут главная бытовая выгода.
- **Переехать вместе с разбором `GameScene`.** Отклонено, причина выше: неразличимость причин
  поломки.
